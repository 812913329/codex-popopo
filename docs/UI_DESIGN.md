# Codex 环境启动器 — UI 决策与验收基线

## 产品定性

- 改动对象：原生 Windows 桌面应用主窗口、环境编辑对话框和技术详情区。
- 页面类型：以后台工具页为能力模型、以轻量启动工具为气质约束；不是仪表盘或营销页。
- 核心用户目标：选择一个环境，并安全启动使用该环境独立数据的 Codex。
- 首屏主任务：看清当前环境与运行状态，点击唯一的主动作。
- 页面气质：原生、安静、可信、高效率。
- 结构负荷：双栏、环境列表独立滚动、主区单一纵向滚动、产品化模态对话框。
- 几何风险：长名称、长路径、中宽窗口、高 DPI、列表滚动和对话框高度。

## Step 0 — 设计态净化

### 删除

- 首页中的 `CODEX_HOME`、`--user-data-dir`、PID、完整命令行和长日志。
- `dev`、`mock`、`test`、`beta`、`localhost`、内部端口等开发态噪音。
- 巨型欢迎 Hero、环境数量统计、启动次数、营销口号和解释布局机制的文案。
- 同一“已隔离/可启动”信息在标题、卡片、徽章之间的重复表达。

### 产品化替换

- `CODEX_HOME` → “Codex 数据”。
- `--user-data-dir` → “应用数据”。
- PID → “运行中”；PID 仅在技术详情中显示。
- 完整 exe 路径 → “已找到 Codex”；原始路径仅在技术详情中显示。
- 原始异常 → 可行动的简短结论 + “查看详情”；完整异常不截断地保留在详情区和本地日志。

### 保留

- 环境名称、环境数据根目录、默认工作目录。
- Codex 检测状态、运行状态和最近启动时间。
- 对用户有决策价值的风险与下一步动作。
- 本机操作者按需查看的完整技术错误。

## 第一轮 — 结构与路径

- 布局：顶部 56 DIP 应用栏；左侧 264 DIP 环境栏；右侧单内容列。
- 首屏配额：只允许“环境侧栏”和“启动主流程”两个同等级大容器。
- 主流程：紧凑环境标题 → 状态化启动面板（**Tab 外固定**）→ **环境配置顶部导航**（概览 / AI / 技能 / 路径 / 高级 / 管理）。
- 主动作：只有一个填充色按钮；当前实现按状态切换为“启动 Codex / 打开 Codex / 重新检测 / 编辑环境 / 打开配置文件”。失败状态不会用含糊的“重试”替代可行动结论。
- 次要动作：编辑、打开目录、复制、重新检测、Tab 内保存使用弱按钮或页脚主按钮；不得与启动主按钮同权并列。
- 危险动作：删除环境会永久删除启动器记录与对应数据目录（需明确确认）；关闭 Codex 需要确认且默认只做正常关闭。确认框使用明确的动作按钮，强制关闭使用红色危险动作，不向用户暴露 Job、root 等内部术语。
- 新建/编辑：模态对话框只突出名称、数据目录和默认工作目录；高级信息下沉。
- 滚动：顶部固定；环境列表独立滚动；主区单一滚动；主动作不得被长内容挤出首屏。

## 第二轮 — 视觉与完成度

- 第一眼：环境名称与状态结论。
- 第二眼：唯一的高对比主按钮。
- 第三眼：数据目录、工作目录和 Codex 检测状态。
- 稳定态不使用庆祝式 Hero；运行后启动面板自动收紧。
- 字体：`Segoe UI Variable Text/Display`，回退 `Segoe UI`；技术路径使用 `Cascadia Mono`。
- 字号阶梯：Page 17 / Profile 22 / Status 18 / Section 13 / Body 13.5 / Caption 12。
- 间距：4 / 8 / 12 / 16 / 24 / 32 DIP；次按钮高 38、主按钮高 42；圆角 8（卡片 10）。
- 色板：固定浅色工具主题（`#F3F4F6` 窗体 / `#FFFFFF` 表面 / 文本 `#16191F`）；强调色低饱和青绿 `#0F766E`，仅用于主按钮、焦点、选中与状态图标。
- 反馈：状态同时使用图形、文字和颜色；错误提供下一步；焦点环 1.5–2px 青绿描边。
- 阴影：卡片最多约 12px blur / 6% 透明度；禁止彩色阴影与玻璃拟态。
- 动画：状态色与背景切换即可；不使用弹跳、位移 hover、大面积渐变。

## 实现前决策快照

- 页面主目标：选择环境并启动独立 Codex。
- 第一眼 / 第二眼：先看当前环境与状态，再点状态化主按钮。
- 主区 / 次区视觉预算：启动与状态优先；配置用顶部 Tab 分类，避免单页混排设置行。
- 主操作位置：主区首屏右侧，不受长路径长度影响；**始终在配置 Tab 上方**。
- 次要内容让位：路径/TOML/运行细节分到路径与高级 Tab；PID、参数和完整路径不进概览。
- 页面气质：轻量桌面工具，拒绝后台仪表盘感与营销页串味。
- 明确 No-Go：大 Hero、三个以上等权大卡、主次按钮同权、首页长日志、只靠颜色表达状态、一键强杀、长路径挤走主动作、中宽窗口把主动作推到首屏外、把侧栏改成第二套应用导航。

## 独立设计复审与最终裁决

| 复审来源 | 关键反对意见 | 裁决 |
|---|---|---|
| 独立 UI 复审 | 双栏容易像企业后台 | 采纳：侧栏只放环境，弱化背景，不增加第二套导航 |
| 独立 UI 复审 | 稳定态大启动面板浪费空间 | 采纳：运行态自动收紧，动作变为“打开 Codex” |
| 独立 UI 复审 | 隐藏技术字段会降低隔离信心 | 采纳：根目录常显，完整技术事实一键展开 |
| 独立 UI 复审 | 青绿色和材质过重会像仿制品 | 采纳：中性主体，强调色只服务交互，纯色回退 |
| 独立 UI 复审 | 停止动作可能损失未保存内容 | 采纳：正常关闭 + 明确动作确认；强制关闭采用二次危险确认 |
| 独立 UI 复审 | 高 DPI 与长路径会挤压主按钮 | 采纳：独立按钮列、路径省略、完整 Tooltip 与复制 |
| 独立 UI 复审 | 单一“重试”无法覆盖配置型错误 | 采纳：按错误类型切换为“重新检测 / 编辑环境 / 打开配置文件” |
| 独立 UI 复审 | 系统 MessageBox 与主界面割裂，且“是/否”要求重读正文 | 采纳：改为同一视觉系统的确认框，按钮直接命名“关闭 Codex / 强制关闭 / 返回” |
| 独立 UI 复审 | 标题、侧栏和状态卡重复表达同一状态 | 采纳：移除标题状态胶囊；保留侧栏扫读状态与承载主动作的状态卡 |

最终视觉取舍以实现后的真实截图、几何量测与 No-Go 复核为准。

## 实现后验收矩阵

- 宽桌面：验证主内容不过度拉伸、无无意义空白。
- 首次布局转折点前后：验证侧栏、路径和按钮不突然膨胀或换行。
- 中宽 awkward width：验证主动作仍在首屏，长路径不挤压按钮。
- 最小支持窗口：验证无横向滚动与控件裁切。
- 125% / 150% / 200% DPI：验证字体、图标、边框和对话框不裁切。
- 浅色 / 深色 / 高对比度：验证状态不只依赖颜色。
- 压力内容：20 个环境、40 字环境名、180 字符路径、8 KB 错误文本。
- 键盘路径：环境选择、新建、浏览目录、启动、查看错误和关闭均可完成。

最终截图必须按真实布局转折点选择宽度，并补充截图证据映射表后才允许宣称 UI 完成。

## v1.1 AI 配置收口（历史）

- 早期：主窗口一条 72 DIP“AI 配置”摘要行 + 模态对话框配置。
- Key 使用普通 TextBox，没有眼睛按钮、掩码或自动隐藏。
- 连接测试为次按钮；保存为配置区唯一填充色主按钮；系统提示词明确“完全替换”及工具调用影响。
- 脏关闭会确认；外部修改冲突时提示重新载入或保留输入。

独立反对视角重点检查：不得让快捷配置成为第二主舞台；不得把连接测试升级为第二主按钮；不得因长 URL/Key 产生横向页面溢出；不得把 Key 重新遮罩；不得将“测试成功”误表述为“已保存”。

## v1.2 环境配置顶部导航 + 技能库

### 信息架构

```text
环境名 + 数据根                    [编辑环境]
┌──────── 启动面板（固定） ──────── [启动/打开 Codex] ─┐
└─────────────────────────────────────────────────────┘
[概览] [AI] [技能] [路径] [高级] [管理]   ← 水平 Tab 条
┌─ 当前 Tab 内容 ─────────────────────────────────────┐
└─────────────────────────────────────────────────────┘
```

| Tab | 内容 | 说明 |
| --- | --- | --- |
| 概览 | AI 摘要、技能计数摘要、工作目录摘要；「打开 AI / 管理技能」 | 扫读，不做重表单 |
| AI | 原 AI 对话框主体：API 连接 / 系统提示词 / 测试与刷新 / 保存 | 高频；页内主路径，非模态 |
| 技能 | 左列表（搜索+开关）+ 右 `SKILL.md` 编辑；安装全部 / 导入 / 打开目录 | 改的是本环境副本 |
| 路径 | 数据根、工作目录、Codex 检测 | 原「环境设置」行 |
| 高级 | 运行详情 + TOML 编辑器 | 原折叠区上移为 Tab |
| 管理 | 复制 / 删除 | 危险动作保持弱样式/危险样式分离 |

### 交互约束

- 启动按钮**不得**进入 Tab 内容区，避免配置分类时丢失主任务。
- AI Tab 页脚：重新载入 + 保存（填充主按钮）；测试连接 / 刷新模型保持次按钮。
- 推理强度下拉：`minimal` … `xhigh`、`max`、`ultra`。
- 技能开关即时落盘；编辑 `SKILL.md` 需显式保存；未保存时切换环境/关闭会确认。
- 技能 Tab 不得把「安装全部」做成与启动同权的大主按钮。
- 侧栏仍只放环境列表；配置分类只在**已选环境**的主内容区。

### 相对 v1.1 的变更

- AI：从「摘要行 → 配置弹窗」**上移**为环境页一级 Tab。
- 原单页混排「环境设置」卡片改为 Tab 分类，降低频繁配置的滚动与点击成本。
- 新增技能库展示与配置面。

### 验收要点（UI）

- 选中环境后立即看到 Tab 条，且启动面板仍在首屏可达。
- 不打开独立对话框即可完成 AI 保存与技能开关。
- 中宽 / 最小窗口下 Tab 标签不裁切主动作；长路径仍省略。
- 既有 No-Go（大 Hero、多主按钮、首页长日志）继续适用。
